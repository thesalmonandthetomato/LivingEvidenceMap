LivingEvidenceMap full-text coding prompt
Schema version: fulltext_coding_v1
Primary extraction basis: FRB Blue Food data extraction sheet
Additional thematic coding: data/reference/topic_ontology_v3.csv

TASK
Code one document using the supplied schema and ontology. Keep extraction simple and aligned with the FRB Blue Food extraction sheet. Return one valid JSON object only.

DOCUMENT COMPLETENESS — HARD RULE
First determine whether the supplied full text appears complete enough to code. If the document is clearly incomplete, truncated, corrupted, or only a fragment such that reliable article-level coding is impossible, return document_type = null and leave ALL substantive coding fields blank/null/empty as appropriate. Do not infer or salvage substantive coding from an incomplete document. In this case, document_completeness_evidence is REQUIRED: provide the first ~250 words of the supplied document (or all available opening text if shorter) and a concise reason why the document is incomplete. This is a data-quality failure, not a substantive article classification.

CLOSED VOCABULARIES — HARD RULE
All controlled-vocabulary fields are closed. Use ONLY values supplied in coding_schema_v1.json. Never invent, paraphrase, abbreviate, translate, or substitute a new enum value. Multiple values are allowed where applicable; never use mixed. If no allowed value fits, use null, an empty array, not_stated, or not_applicable as appropriate and preserve the paper's terminology only in free-text evidence. Never create an 'other' category except the explicit document_type value 'other'.

DOCUMENT SCOPE AND REVIEW HIERARCHY
Code what this document itself investigates, measures, compares, models, evaluates, or reports. A review is coded as document_type = review. review_type is then coded beneath review as either primer_overview or systematic_style. Use systematic_style if the review calls itself a systematic review, systematic literature review, systematic-style review, or equivalent; OR if it describes ANY methodology for identifying, selecting, searching, appraising, synthesising, or otherwise systematically handling the literature; OR if it uses quantitative measures to combine primary study findings. Otherwise use primer_overview.
Reviews may be coded based on the body of articles they review when those characteristics are representative of the review as a whole. For reviews, code species, facility, production stage, setting, study population, etc. only when the review's coverage as a whole supports those values; do not select a value solely because it occurs in one isolated included article. Commentary, editorial, perspective, book, and book chapter should not inherit empirical study variables from studies they merely discuss. Reports/theses/protocols should likewise be coded according to what the document itself does.

COMPOUND / MULTIPLE-STUDY DOCUMENTS — RARE HUMAN REVIEW FLAG
Do not automatically split a document. The flag is intended for a SMALL MINORITY of records with strong evidence of multiple analytically distinct studies or empirical components. Set multiple_studies_flag = true ONLY when the full text provides strong, positive evidence that two or more separately codable studies/components are present. Strong evidence includes: explicitly labelled Study 1/Study 2 or equivalent; a thesis/dissertation containing multiple substantive empirical chapters; clearly separate study aims/questions with corresponding separate methods and results; clearly separate samples/populations with distinct methods and results that function as independent studies; or an article that explicitly combines two independently structured empirical studies, such as a distinct impact/exposure study and a distinct mitigation/intervention study. Multiple values in fields, non-pairwise combinations, different outcomes, different assays, or different experimental conditions ALONE are NOT sufficient evidence and should NOT trigger the flag. A methods comparison or multiple assay types within one coherent study is normally one study. If evidence is ambiguous, set multiple_studies_flag = false. When true, give a concise multiple_studies_reason identifying the concrete evidence for separate studies and why human review may be needed. Do NOT infer pairwise relationships merely to avoid the flag. This is a human-review flag, not an error and not a reason to fail the workflow.

EVIDENCE PRIORITY
For substantive study characteristics, population, facility, system, intervention/exposure, comparator and outcomes: prefer Methods/Materials, then Results/Findings. For research question and objectives, use the Introduction as needed, including earlier introductory material when it clearly establishes the question/aims. Use the Abstract ONLY as an extreme fallback when the information cannot be established elsewhere in the full text.

RESEARCH QUESTION AND OBJECTIVES — REQUIRED FOR COMPLETE STUDIES
For every complete empirical study, modelling study, review, thesis, report, protocol, or other substantive research document, provide BOTH research_question and objectives_summary whenever the full text contains enough information to establish them. These must be grounded in the document's own text, not inferred solely from the title, abstract, or our interpretation of the methods/results. Provide evidence for BOTH fields. Evidence may come from the Introduction; the Abstract is an extreme fallback only.

OUTCOME EVIDENCE — HARD RULE
outcome_measured and impact_type/impact_details must be based ONLY on data actually collected, measured, analysed, or reported as study results by the document itself. Evidence for these fields may come ONLY from Methods/Materials or Results/Findings, including tables and figure legends/captions. Do NOT use evidence from the Abstract, Introduction, Discussion, Conclusions, background, literature review, references, or cited literature for these fields. If a proposed outcome/impact is supported only outside Methods/Results, leave that outcome/impact field null/empty.

STUDY TYPE
Use only the closed study_type vocabulary: experimental, observational, modelling, not_stated, not_applicable. Experimental means investigators deliberately manipulate or impose a condition on study subjects/specimens. Laboratory assays performed only on already-collected material are NOT experimental merely because they occur in a laboratory. If subjects/specimens are only observed, measured, sampled, assayed, sequenced, or analysed without deliberate manipulation by investigators, do NOT code experimental.

STUDY DESIGN
Use only: BA, CI, BACI, RCT, Time-series, Modelling, Qualitative, not_stated, not_applicable. CI is appropriate for genuine comparison of intervention/treatment conditions, including deliberately imposed alternative challenge modes such as injection versus immersion. Time-series includes repeated longitudinal/repeated-measures temporal sampling. Do not create longitudinal as a new value.

RESEARCH APPROACH
Only: quantitative, qualitative, mixed_methods, not_applicable.

SETTING — STUDY SETTING ONLY
Only: field, laboratory, in_vitro, in_silico. Setting describes WHERE the substantive observational or experimental study itself was conducted, not where routine sample processing or laboratory analysis was subsequently performed. A field/production-facility study does NOT become laboratory merely because samples are processed or analysed in a laboratory. Code laboratory only when the substantive study itself is conducted in a controlled laboratory/research-facility setting. A hatchery, farm, sea cage, land-based farm, or other aquaculture production facility is not automatically laboratory. Never put marine, freshwater, hatchery, land_based, RAS, open_cages, or closed_cages in setting.

SPECIES / POPULATION / SAMPLE UNIT / FACILITY / SYSTEM
species is REQUIRED, is a CLOSED ARRAY, and may contain ONLY: Atlantic salmon; chum salmon; pink salmon; coho salmon; chinook salmon; sockeye salmon; masu salmon; rainbow trout; unspecified salmon species. If the paper explicitly names a permitted species relevant to the study, code it even when the immediate material is a parasite, pathogen, isolate, sediment, or other material attributable to that host. Use unspecified salmon species ONLY when no permitted named species is explicitly established. species must NEVER be null or empty for a complete relevant document.
other_farmed_species = free-text array for additional farmed species outside the nine-value salmonid vocabulary, e.g. brown trout.
study_population = WHAT population/material is actually studied.
sample_unit = SIMPLE HIGH-LEVEL ARRAY. Record only obvious substantive units such as fish, cells, people, farms, communities, grab samples, tanks, or households. Do NOT reconstruct experimental units, pseudoreplication, nesting, or statistical unit-of-analysis. Do NOT enumerate nested organisms, parasites, tissues, subsamples, assays, or derived measurements merely because they occur in the Methods. Do not use a species name as sample_unit. Use multiple values only when genuinely distinct high-level unit types are independently sampled or observed.

There is ONE facility/production-system variable: aquaculture_facility. Do not create farming_system as a separate field.

AQUACULTURE FACILITY — CLOSED VOCABULARY
Only: salmon_farming_region, hatchery, open_cages, closed_cages, land_based, land_based_RAS.
Use aquaculture_facility only for the salmon aquaculture production facility/system in which the substantive study was conducted or the production system being evaluated, when explicitly stated or clearly and unambiguously identified.
If setting is clearly laboratory or in_vitro, aquaculture_facility MUST be null/empty unless the facility itself is explicitly the object/context of study. Laboratory circulation of water is NOT RAS. Code land_based_RAS only when the actual study system is explicitly identified as a land-based recirculating aquaculture system/RAS or recognised equivalent.
hatchery: code when the substantive study was explicitly conducted at/in a hatchery facility or the hatchery is explicitly the aquaculture production system in which studied fish/material were held or sampled. Do not reject hatchery merely because the facility also has conservation or research functions. Do not infer hatchery solely from life-stage terminology.
open_cages: sea pens/open net pens/open cages. For a substantive study conducted in a sea cage, code open_cages by default unless explicitly described as closed.
closed_cages: explicitly described closed cages with impermeable sides/walls or recognised equivalent.
land_based: explicitly described land-based aquaculture production not identified as RAS.
land_based_RAS: explicitly described land-based recirculating aquaculture production/RAS or recognised synonymous term.
salmon_farming_region: only when explicitly identified as a salmon-farming region rather than merely naming a farm/location.
Never use wild, mixed, genetic variety/strain, river, marine, freshwater, recirculating alone, or invented values in aquaculture_facility.

GENETIC VARIETY
Keep strain/genetic variety separate from aquaculture_facility; record it only in the appropriate free-text field/evidence.

SYSTEM STUDIED
system_studied = the biological, environmental, social system or material actually examined, e.g. sediment, water column, fish gut, fillet tissue, whole fish, farm workforce, supply chain, river ecosystem.

PRODUCTION STAGE — CLOSED VOCABULARY
Only: Feed, Hatchery, Transfer between Hatchery and Adult, Adult grow-out, Processing. Production stage describes the aquaculture production context relevant to what the study investigates, including the production context of material/processes studied. It is NOT the same as fish_life_stage.
CRITICAL FEED RULE: Feed means the production/manufacture of feed outside an aquaculture facility. Do NOT use Feed merely because a study tests feed, diets, feed additives, alternative feeds, or feeding efficiency on fish. For such studies, use the relevant fish production stage when explicitly established (e.g. Adult grow-out), or NULL when the study is laboratory-based and no aquaculture production stage is applicable. Salmon are never themselves in a Feed production stage.
Use Adult grow-out for substantive studies of processes/materials associated with adult grow-out production, including faeces, wastes, cages, water, sediments, or other outputs where the paper explicitly frames the process in the adult grow-out system. Use Hatchery only when the paper explicitly identifies hatchery production as the production context. Use Transfer between Hatchery and Adult only where the study explicitly concerns that transfer process. Use Processing when the study concerns processing of harvested aquaculture product.

FISH LIFE STAGE — CLOSED VOCABULARY
fish_life_stage is an ARRAY and may contain multiple values. Use ONLY: Sperm, Egg, Embryo, Alevin, Fry, Parr, Smolt, Juvenile, Adult, Broodstock, Harvest, Product. Code the biological life stage(s) actually studied, independent of production_stage. Do not infer from facility alone. Before returning JSON, scan Methods/Materials and Results for explicit life-stage terminology and ensure every substantive stage actually studied is represented.

EXPOSURE / INTERVENTION / COMPARATOR / MITIGATION — HARD RULE
intervention = deliberate treatment, manipulation, mitigation measure, vaccination, husbandry change, challenge, or other assigned experimental action.
exposure = an observational exposure whose relationship with an outcome/impact is investigated. Geography, season, farm, host group, or descriptive grouping is NOT automatically an exposure.
When mitigation is tested, intervention is the priority; do not automatically also code exposure. Both only where the same article explicitly measures an exposure/impact relationship AND tests a mitigation intervention.
comparator = ONLY the actual comparison group, site, treatment condition, or intervention condition against which the focal intervention/exposure is compared. Comparator may be null where no genuine comparison exists.
mitigation_evaluation = ONLY a measure intended to prevent, reduce, control, or mitigate an adverse impact in the focal system. Do NOT populate for general treatment efficacy, drug susceptibility, diagnostic assays, assay validation, methodological comparison, or methodological performance unless the evaluated measure is explicitly a mitigation/control measure for an adverse impact.

OUTCOMES / IMPACTS
outcome_measured = substantive outcomes actually measured/assessed by this document. impact_type and impact_details follow the established extraction-sheet structure where applicable. Do not invent ad-hoc impact_type labels such as physiological impact, health-related biological response, or environmental merely to describe an outcome. Populate impact_type only where an established extraction-sheet/ontology category is applicable, and use the established terminology.

METHODOLOGY
methodology_for_data_collection = actual data-collection methods, using paper terminology where possible. Do not confuse a laboratory analytical method with experimental study type.

ONTOLOGY
Apply data/reference/topic_ontology_v3.csv at the same conceptual level used for abstract coding. Use exact path_id values and apply include_when, exclude_when and prompt_logic_note. Prefer the most specific supported node. Do not code topics merely mentioned in background, limitations, or discussion. Provide evidence for selected ontology codes.

METHODS ONTOLOGY
Only code a Methods ontology branch when methodological development, validation, comparison, or evaluation is itself a substantive contribution. Do not code Methods merely because a paper has a Methods section.

FINAL PRE-RETURN AUDIT — REQUIRED
Before returning JSON, check: controlled-vocabulary values are permitted; no mixed; species is one of the nine for complete relevant documents; setting is substantive study setting; laboratory processing of field samples has not been mistaken for laboratory setting; laboratory/in_vitro facility is null unless facility itself is studied; Feed production stage is ONLY feed production/manufacture outside aquaculture facilities; fish_life_stage captures every explicitly stated substantive life stage; sample_unit remains high-level; exposure is not inferred from grouping variables; mitigation_evaluation is reserved for actual mitigation/control; outcomes and impact evidence come only from Methods/Results/figure/table legends; multiple_studies_flag is rare and has strong positive evidence when true; incomplete documents have required completeness evidence and no substantive coding; research_question and objectives are grounded in stated aims/questions; and no legacy or invented controlled-vocabulary value has been generated.
