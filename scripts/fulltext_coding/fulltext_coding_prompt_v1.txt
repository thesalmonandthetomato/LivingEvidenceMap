LivingEvidenceMap full-text coding prompt
Schema version: fulltext_coding_v1
Ontology: data/reference/topic_ontology_v3.csv

TASK

Code one document using the supplied structured schema and the supplied LivingEvidenceMap ontology. Return valid JSON only.

DOCUMENT TYPE — USE ONLY THIS SINGLE TAXONOMY

Choose exactly one document_type:
study, review, systematic_review, perspective, commentary, editorial, book, book_chapter, report, thesis, protocol, other

Do not use journal_article, conference_paper, primary_research, or contribution_type. A thesis and dissertation are both coded as thesis.

For document_type = review, review_type must be systematic or non_systematic. For all other document types, review_type = not_applicable.

GENERAL PRINCIPLES

- Code what the document actually investigates, measures, compares, models, evaluates, or reports.
- Do not infer substantive topics from background discussion alone.
- If evidence is insufficient, use null, an empty array, or not_applicable rather than inventing information.
- Return the exact top-level schema. Do not wrap fields inside a `fields` object.

EVIDENCE PRIORITY

1. Methods and Materials
2. Results / Findings
3. If the research focus remains unclear, inspect only the final two paragraphs of the Introduction/Objectives.

Do not use the rest of the Introduction/background to infer substantive coding when Methods or Results provide no support.

STUDY CHARACTERISTICS

For studies and research-bearing reviews/theses/reports where applicable:
- study_design: experimental, observational, laboratory, in_vitro, in_silico, modelling, other, not_applicable
- research_approach: quantitative, qualitative, mixed, not_applicable
- setting: field, laboratory, in_vitro, in_silico, mixed, not_applicable
- sample_size and sample_unit
- study_period
- location_region and location_country
- species: use the supplied salmon species controlled vocabulary when available
- population: sea_pen, hatchery, river, land_based, wild, mixed, other, not_applicable
- outcome_measured
- intervention
- comparator

Do not force inapplicable fields.

RESEARCH QUESTION

Provide one concise, consistently phrased research question capturing what the document actually investigates.
Use causal language only when justified. For descriptive work, use a descriptive question; for modelling/methods, ask about estimation, prediction, performance, or validation.

OBJECTIVES SUMMARY

Provide a brief 1–2 sentence paraphrase of the objective(s). Use Methods/Results primarily and the final two Introduction/Objectives paragraphs only when necessary.

ONTOLOGY CODING

For each selected ontology code:
- use the exact path_id from data/reference/topic_ontology_v3.csv;
- apply include_when/exclude_when and prompt_logic_note;
- do not code topics merely mentioned in background, limitations, or discussion;
- prefer the most specific supported node.

METHODS

Only code the ontology Methods branch when methodological development, validation, comparison, or evaluation is itself a substantive contribution. Do not code Methods simply because the paper has a Methods section.

EVIDENCE

For every substantive coded field, provide concise supporting evidence from Methods/Results where possible. Each evidence item must contain field, value, text, section, and page (null if unavailable).

OUTPUT

Return one JSON object matching coding_schema_v1 exactly, with all substantive fields at the top level.
