LivingEvidenceMap full-text article coding prompt
Schema version: fulltext_coding_v1

TASK
Code the supplied full text into the current LivingEvidenceMap JSON schema. The schema and this prompt are the sole coding authority. Extract from the article itself. Return exactly one valid JSON object conforming to the schema, with no commentary or extra fields.

CURRENT EXTRACTION FIELDS
The substantive extraction fields are exactly:
- document_type
- review_type
- study_type
- study_design
- research_approach
- setting
- sample_unit
- study_period
- location_region
- location_country
- species
- other_farmed_species
- study_population
- aquaculture_facility
- system_studied
- production_stage
- fish_life_stage
- exposure_intervention
- comparator
- outcome_measured
- funding_body
- research_question
- objectives_summary
- ontology_codes
- multiple_studies_flag
- multiple_studies_reason

Do not add fields. In particular, do not return sample_size, impact_type, impact_details, methodology_for_data_collection, funder, exposure, intervention, mitigation_evaluation, or any other legacy/removed extraction field. Exposure and intervention are one combined field: exposure_intervention.

Return only the substantive fields above plus the schema-defined audit structures: document_completeness, document_completeness_evidence, field_completeness, and not_reported_fields. Do not return workflow provenance or other metadata unless the schema explicitly requires it.

ELIGIBLE-SPECIES FILTER
First identify the eligible salmon/farmed-salmon species and components. Only information concerning eligible species/components may support substantive coding. Where eligible and ineligible species/components occur in the same document, keep them separate. Never combine characteristics, methods, populations, settings, locations, exposures, comparators or outcomes across eligible and ineligible components.

EVIDENCE AND SOURCE DISCIPLINE
Every populated substantive field must have a field-specific evidence entry. Evidence must support that exact field and value, not merely be generally relevant to the article. Use the article/full text as the source of evidence. Do not use model knowledge as evidence.

For primary empirical studies, Methods/Materials and Methods and Results/Findings are the controlling evidence sources for empirical and study-method variables. Search them thoroughly, including tables and figure legends/captions. Other sections may support descriptive/system-context fields where this prompt explicitly permits it.

For non-primary documents such as reviews, perspectives, commentaries, editorials, books, book chapters and reports, extract the document's own explicit system/context information. Such information may occur in the title, abstract, introduction, discussion, conclusions, tables, figures or other sections. Do not discard explicit system/context information merely because it is outside Methods/Results.

Evidence must be specific enough to demonstrate why the coded value is correct. If a permitted inference is made, preserve the underlying article evidence and state in the evidence entry that the value is an inference permitted by this prompt.

Do not use an abstract, introduction, discussion, cited study or general knowledge to override contradictory Methods evidence for a primary empirical study. This does NOT prevent using the Abstract or Introduction to extract the document's own research question and objectives, as explicitly required below.

DOCUMENT TYPES AND NON-PRIMARY DOCUMENTS
Code what the document itself investigates, evaluates, synthesises, discusses or explicitly describes, restricted to eligible species/components.

Reviews, perspectives, commentaries, editorials, books, book chapters and reports may contribute explicit system/context information for eligible salmon/farmed-salmon content, including:
- species
- other_farmed_species
- location_region
- location_country
- aquaculture_facility
- system_studied
- production_stage
- fish_life_stage
- setting
- exposure_intervention

These variables may be extracted from system/context descriptions even when they are not study methods. Do not construct an empirical study from cited studies.

For these non-primary documents, do not invent an empirical study population, sample unit, empirical study period, empirical design, comparator or empirical outcome merely because cited studies are discussed. Code the document's own research question/objectives where explicitly stated.

REVIEWS
review_type = systematic_style if the document calls itself a systematic review/systematic literature review/systematic-style review or equivalent, describes a methodology for identifying/selecting/searching/appraising/synthesising literature, or quantitatively combines primary-study findings. Otherwise use primer_overview for a review.

STUDY TYPE, DESIGN AND APPROACH
study_type only: experimental, observational, modelling, not_stated, not_applicable.
- Experimental requires deliberate manipulation/imposition on eligible study subjects/specimens.
- Laboratory processing or analysis of field-collected material is not experimental by itself.
- Deliberate action imposed on eligible fish/specimens is experimental unless it is only processing/analysis of field samples.
- A non-primary document without its own eligible empirical study uses not_applicable.

study_design only: BA, CI, BACI, RCT, Time-series, Modelling, Qualitative, not_stated, not_applicable.
- CI includes genuine intervention/treatment comparisons, including deliberately imposed alternative challenge modes such as injection versus immersion.
- Do not create new design labels.
- A non-primary document without its own eligible empirical study uses not_applicable.

research_approach only: quantitative, qualitative, mixed_methods, not_applicable.
- A non-primary document without its own eligible empirical study uses not_applicable.

SETTING
Only: field, laboratory/controlled facility, in_vitro, in_silico.

For primary studies, setting describes where the substantive eligible-species study occurred, not where samples were later processed.
- field includes real-world farms, sea cages, hatcheries, rivers, lakes and coastal/environmental locations, including controlled field experiments;
- laboratory/controlled facility includes laboratories, research facilities, tanks, controlled aquaculture facilities and flow-through raceways when these constitute the substantive study environment;
- in_vitro applies to cell/culture experiments;
- in_silico applies to computational/modelling studies.

Do not classify a study as field merely because it occurred on a farm, university site or other real-world premises. A controlled aquaculture experiment in tanks or a research facility is laboratory/controlled facility. Laboratory processing of field-collected samples does not make the study laboratory.

For non-primary documents, setting may describe an explicitly stated eligible salmon/system context.

SPECIES
species may ONLY contain:
- Atlantic salmon
- chum salmon
- pink salmon
- coho salmon
- chinook salmon
- sockeye salmon
- masu salmon
- rainbow trout
- unspecified salmon species

If a permitted named species is explicitly linked to the eligible study component or system/context, code it. Explicit Chinook salmon must be coded as chinook salmon. Use unspecified salmon species only when no permitted named species is explicitly established. For salmon-lice documents without an explicitly established permitted salmonid host, use unspecified salmon species.

other_farmed_species is a free-text array for additional farmed species outside the permitted species vocabulary. Do not allow an ineligible species to populate other substantive fields.

STUDY POPULATION
study_population is the actual eligible population/material studied by the document. For a non-primary document without its own eligible empirical study, do not construct a population from cited studies.

SAMPLE UNIT
sample_unit is a simple high-level methodological unit when clearly identifiable. Prefer ONE primary methodological unit such as fish, cells, farms, communities, grab samples or households. Do not reconstruct nesting, pseudoreplication, statistical units, technical subsamples, parasites, tissues, assays, derived measurements or tanks merely used as containers. Do not use a species name as sample_unit.

When downstream biological material is analysed but the fish are the primary experimental/methodological unit, prefer the primary unit rather than returning both levels. For example, bacterial isolates derived from fish do not automatically become a second sample unit when the experimental comparison is between fish groups.

Do not calculate or infer a sample size. Sample size is not an extraction variable.

LOCATION
For primary studies, use explicit study-setting information from Methods/study setting and relevant Results. For non-primary documents, an explicit eligible salmon/system location anywhere in the document may support location_region/location_country.

Do not confuse the origin of a pathogen, strain, feed ingredient, cited study or other material with the location of the eligible study/system unless the document explicitly establishes that connection.

AQUACULTURE FACILITY
aquaculture_facility is the facility/production-system context for the eligible salmon aquaculture system. Only:
- salmon_farming_region
- hatchery
- open_cages
- closed_cages
- land_based
- land_based_RAS

Code only an explicitly stated eligible salmon aquaculture production facility/system in which the study was conducted or an eligible salmon production system explicitly described/evaluated. Non-primary documents may populate this field from explicit system-level descriptions.

- hatchery requires explicit hatchery production context;
- open_cages includes sea pens/open net pens/sea cages unless explicitly closed;
- closed_cages requires explicit closed impermeable sides/walls or recognised equivalent;
- land_based requires explicit land-based aquaculture not identified as RAS;
- land_based_RAS requires explicit land-based RAS or recognised equivalent;
- salmon_farming_region requires an explicit regional salmon-farming context.

Do not infer a facility from life stage alone. Laboratory water circulation is not RAS. Do not force a research station or laboratory into a production-facility category unless it also explicitly constitutes one of the permitted aquaculture production-system categories. If the source facility is only a research facility and no permitted aquaculture facility applies, use JSON null when the field is inapplicable; use NOT FOUND only when a permitted facility is applicable but not reported.

SYSTEM AND PRODUCTION STAGE
system_studied is the biological, environmental, social system or material actually examined for eligible components, or the explicitly described eligible salmon/system context in a non-primary document.

production_stage only:
- Feed
- Hatchery
- Transfer between Hatchery and Adult
- Adult grow-out
- Processing

Production stage describes the aquaculture production context actually studied or explicitly evaluated, and is independent of fish_life_stage. Do not automatically code the source/rearing history of experimental fish as the production stage of the study.
- Feed means production/manufacture of feed outside an aquaculture facility. Studies testing diets/feed on fish are not automatically Feed.
- Hatchery requires explicit hatchery production context and should be used when hatchery production itself is the relevant studied/evaluated production context.
- Transfer between Hatchery and Adult requires explicit transfer context.
- Adult grow-out includes explicitly framed grow-out fish and associated grow-out wastes, faeces, cages, water, sediments or other outputs.
- Processing concerns processing of harvested aquaculture product.

For a controlled experimental study using juveniles or other fish merely sourced from a hatchery, do not code Hatchery solely because the fish originated there. For an environmental study of sediment/water/waste associated with adult grow-out, code Adult grow-out when the full text explicitly establishes that context.

For non-primary documents, do not infer production_stage merely from a generic reference to aquaculture.

FISH LIFE STAGE
fish_life_stage only:
- Sperm
- Egg
- Embryo
- Alevin
- Fry
- Parr
- Pre-smolt
- Smolt
- Juvenile
- Adult
- Broodstock
- Product

Harvest is NOT a fish_life_stage value. Harvest belongs only to production_stage/context and must never be emitted in fish_life_stage.

Code all substantive eligible fish life stages actually established in the document. For primary empirical studies, search the entire Methods and Results, including study-period descriptions, production descriptions, tables and figure legends, for later substantive stages in the same eligible cohort. For non-primary documents, search the entire document for explicit life-stage statements.

Production stage and fish life stage are independent variables, but they may describe the same cohort at different levels. If fish reach harvest after a production/grow-out period, do not code Harvest as a life stage; code the biologically supported life stage, normally Adult where the Methods support adult/grow-out status.

LIFE-STAGE INFERENCE FROM METHODS
For primary empirical studies, life stage may be inferred from body mass, age, developmental descriptors or production information ONLY when the supporting information appears in Methods/Materials and Methods or equivalent study-design text for the fish being coded. Do not infer life stage from the Introduction, Discussion, abstract, title, cited literature or general knowledge alone.

Use this conservative salmon-specific body-mass guideline:
- Atlantic salmon >=1.0 kg may be coded Adult when the fish are in grow-out/production context or otherwise clearly beyond juvenile/smolt size and no contradictory designation is given.
- Atlantic salmon 0.5 to <1.0 kg is borderline and requires additional Methods context supporting Adult.
- Atlantic salmon <0.5 kg must not be coded Adult from mass alone.
- For other large-bodied salmon species without a species-specific threshold, the >=1.0 kg Adult rule may be used only when Methods establish a clearly post-juvenile/smolt production context.
- Never infer Smolt, Parr, Fry or Juvenile from body mass alone unless the Methods provide additional supporting context.
- If Methods show progression through multiple substantive life stages in the same eligible cohort, code all supported stages.

Pre-market is not itself a permitted fish-life-stage value. If Methods explicitly describe pre-market fish as Adult, Adult may be coded. Do not automatically convert pre-market to Adult.

If a study follows fish through production to harvest, use Methods evidence about age, size, maturation, smolt transfer, grow-out or other developmental descriptors to determine the corresponding fish_life_stage. Do not treat the word "harvest" alone as evidence of Adult; use the permitted inference rules and actual Methods context.

EXPOSURE + INTERVENTION
There is ONE and ONLY ONE combined field: exposure_intervention. Do not create separate exposure or intervention fields under any circumstance. The output keys `exposure` and `intervention` are forbidden legacy fields and must never appear.

For primary empirical studies, code the actual eligible-species intervention and/or exposure studied.
- A deliberate assigned treatment, manipulation, vaccination, deliberately imposed husbandry change, challenge or other assigned experimental action is an intervention.
- An investigated observational exposure or explicitly characterised exposure context may be coded as an exposure.
- Routine rearing, ordinary husbandry, sampling, culture conditions or laboratory processing are not automatically interventions unless deliberately assigned/imposed as the condition being tested.
- Environmental, dietary, geographic, production-system, seasonal, farm or host-group conditions may be exposures when actually investigated or explicitly characterised as the exposure/context of interest.
- A generic environmental mention is not automatically an exposure.

For non-primary documents, exposure_intervention may contain an explicit eligible salmon/system-level exposure or intervention context described by the document itself. Do not inherit an intervention/exposure from a cited study merely because that study is discussed.

COMPARATOR
comparator is only the actual focal comparison within eligible empirical evidence. It may be null when no genuine comparison exists. Do not treat every grouping, stratification, outcome category, survivor/mortality category, time point, pathogen, treatment component or analytical subgroup as a comparator. Do not inherit a comparator from cited studies.

OUTCOME MEASURED
outcome_measured contains substantive outcomes actually measured/assessed using study data and reported by the eligible-species primary study.

For primary empirical studies, use Methods/Materials and Results/Findings, including tables and figure legends/captions. Do not code an outcome merely because it is mentioned in the title, abstract, Introduction, Discussion, Conclusions or cited literature.

For non-primary documents without their own eligible empirical study, do not transfer outcomes from cited studies into the record.

FUNDING
funding_body is taken from explicit funding statements, acknowledgements or equivalent full-text attribution. Do not infer a funder from author affiliation, institutional address or publisher.

RESEARCH QUESTION AND OBJECTIVES
These two fields are mandatory retrieval targets, not optional descriptive fields.

For every complete document, actively search the Abstract and Introduction for the document's own explicit research question, aim, purpose, objective(s), hypothesis or equivalent statement BEFORE considering either field NOT FOUND. Search the Methods/Results as a secondary check for explicit restatements of the aims. For reviews and other non-primary documents, use the document's own stated question/objectives, not the aims of cited studies.

If an explicit question is stated, populate research_question with a faithful concise representation supported by evidence from the Abstract/Introduction. If no question is explicitly phrased as a question but the aim/purpose/objective is explicit, convert that explicit aim into a concise research-question formulation without adding substantive content not present in the article.

Populate objectives_summary from explicit aims/objectives/purpose statements. It may be supported by the Abstract or Introduction. Do not leave research_question or objectives_summary unpopulated merely because the article uses "aim", "objective", "purpose", "we investigated", "we compared", "we evaluated", "we examined", "this study sought to", or equivalent wording rather than the word "question".

Only after actively checking the Abstract and Introduction and finding no usable statement may either field be marked NOT FOUND. Do not infer a question/objective solely from the Methods or Results when the article provides no explicit aim/purpose/objective statement.

ONTOLOGY CODES
ontology_codes should represent the eligible-species substantive topic/method content according to the repository's current topic ontology. Use only valid ontology codes. Do not invent codes.

MULTIPLE STUDIES
Set multiple_studies_flag = true only with strong positive evidence of two or more independently structured eligible-species studies/components, such as explicitly labelled studies, separate substantive thesis chapters, separate study aims/questions with corresponding separate methods/results, distinct eligible samples/populations with distinct methods/results functioning as independent studies, or explicitly combined independent eligible empirical studies.

Multiple treatments, factor levels, conditions, time points, assays, outcomes or populations within one coherent design do not by themselves constitute multiple studies. Discussion of multiple cited studies in a review/commentary/perspective does not by itself make the flag true. If ambiguous, use false.

When multiple_studies_flag = false, multiple_studies_reason MUST be JSON null. When true, multiple_studies_reason must give a concise evidence-based reason.

DOCUMENT COMPLETENESS
First assess whether the supplied full text is complete enough for substantive extraction.

If the supplied full text is clearly incomplete, truncated, corrupted, malformed or only a fragment, set document_completeness = INCOMPLETE and do not perform substantive extraction. Set substantive fields to the schema-valid neutral states appropriate for an incomplete document. document_completeness_evidence must provide the opening text (approximately 250 words, or all available opening text if shorter) plus a concise reason for the incompleteness.

Do not interpret a missing section in a demonstrably incomplete full text as evidence that the article did not report the variable. Such a record must be eligible for later reassessment when a complete full text becomes available.

COMPLETENESS AUDIT
Actively assess every current substantive extraction field.

For each current field:
1. Determine whether it applies to the document/component.
2. Search the appropriate full-text evidence.
3. Code explicit information, or make only an inference explicitly permitted by this prompt.
4. If the field applies but is not reported in the available complete text, mark it "NOT FOUND".
5. If the field is genuinely inapplicable to the document/component, use JSON null.

The only permitted field_completeness values are:
- "NOT FOUND"
- JSON null

Never use "FOUND". Never use any other completeness status.

Populated fields are omitted from field_completeness. Applicable but unreported fields must appear in not_reported_fields. Genuinely inapplicable fields must not appear in not_reported_fields.

not_reported_fields must be mechanically identical to the set of current substantive fields whose field_completeness value is "NOT FOUND". Do not independently invent this list.

Every populated current field must have field-specific evidence. The evidence must support the exact field/value. Evidence for one field must not be reused as if it supported a different field unless the same text genuinely supports both.

CONTROLLED VOCABULARIES AND OUTPUT HYGIENE
Use only values supplied by the current coding schema. Never invent, paraphrase, abbreviate, translate or create a new controlled-vocabulary value. If no allowed value fits, use the appropriate null/NOT FOUND state and preserve useful paper terminology only in free-text evidence.

Before returning the JSON, perform a final self-check:
- exactly the 26 current substantive fields are present, plus only schema-defined audit/evidence structures;
- no removed/legacy field is present;
- no field or status contains the literal value "FOUND";
- `exposure_intervention` is the only field used for exposure/intervention and the legacy keys `exposure` and `intervention` are absent;
- sample_size is absent;
- Harvest is absent from fish_life_stage;
- every populated substantive field has field-specific evidence;
- every "NOT FOUND" completeness entry is represented in not_reported_fields;
- no genuinely inapplicable field appears in not_reported_fields;
- multiple_studies_reason is null when multiple_studies_flag is false;
- research_question and objectives_summary were actively checked against Abstract and Introduction before being marked NOT FOUND;
- all controlled-vocabulary values exactly match the schema;
- no information from ineligible species/components has been transferred to eligible coding;
- life-stage inference, if used, is supported by Methods/equivalent study-design text and complies with the rules above.

FINAL OUTPUT
Return exactly one valid JSON object conforming to the current schema. The object may contain only the current substantive extraction fields and schema-defined audit/evidence structures. No other fields are permitted.
