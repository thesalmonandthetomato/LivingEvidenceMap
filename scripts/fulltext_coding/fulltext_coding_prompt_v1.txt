LivingEvidenceMap full-text coding prompt
Schema version: fulltext_coding_v1
Primary extraction basis: FRB Blue Food data extraction sheet
Additional thematic coding: data/reference/topic_ontology_v3.csv

TASK
Code one document using the supplied schema and ontology. Keep extraction simple and aligned with the FRB Blue Food extraction sheet. Return one valid JSON object only.

DOCUMENT COMPLETENESS — HARD RULE
First determine whether the supplied full text appears complete enough to code. If the document is clearly incomplete, truncated, corrupted, or only a fragment such that reliable article-level coding is impossible, return document_type = null and leave ALL other coding fields blank/null/empty as appropriate. Do not infer or salvage coding from an incomplete document. Evidence may be left empty. This is a data-quality failure, not a substantive article classification.

CLOSED VOCABULARIES — HARD RULE
All controlled-vocabulary fields are closed. Use ONLY values supplied in coding_schema_v1.json. Never invent, paraphrase, abbreviate, translate, or substitute a new enum value. Multiple values are allowed where applicable; never use mixed. If no allowed value fits, use null, an empty array, not_stated, or not_applicable as appropriate and preserve the paper's terminology only in free-text evidence. Never create an 'other' category except the explicit document_type value 'other'.

DOCUMENT SCOPE AND REVIEW HIERARCHY
Code what this document itself investigates, measures, compares, models, evaluates, or reports. A review is coded as document_type = review. review_type is then coded beneath review as either primer_overview or systematic_style. Use systematic_style if the review calls itself a systematic review, systematic literature review, systematic-style review, or equivalent; OR if it describes ANY methodology for identifying, selecting, searching, appraising, synthesising, or otherwise systematically handling the literature; OR if it uses quantitative measures to combine primary study findings. Otherwise use primer_overview. Do not use systematic_review as a document_type value.
Reviews may be coded based on the body of articles they review when those characteristics are representative of the review as a whole. For reviews, code species, facility, production stage, setting, study population, etc. only when the review's coverage as a whole supports those values; do not select a value solely because it occurs in one isolated included article. Commentary, editorial, perspective, book, and book chapter should not inherit empirical study variables from studies they merely discuss. Reports/theses/protocols should likewise be coded according to what the document itself does.

COMPOUND / MULTIPLE-STUDY DOCUMENTS — RARE HUMAN REVIEW FLAG
Do not automatically split a document. The flag is intended for a SMALL MINORITY of records with strong evidence of multiple analytically distinct studies or empirical components. Set multiple_studies_flag = true ONLY when the full text provides strong, positive evidence that two or more separately codable studies/components are present. Strong evidence includes: explicitly labelled Study 1/Study 2 or equivalent; a thesis/dissertation containing multiple substantive empirical chapters; clearly separate study aims/questions with corresponding separate methods and results; clearly separate samples/populations with distinct methods and results that function as independent studies; or an article that explicitly combines two independently structured empirical studies, such as a distinct impact/exposure study and a distinct mitigation/intervention study. Multiple values in fields, non-pairwise combinations, different outcomes, different assays, or different experimental conditions ALONE are NOT sufficient evidence and should NOT trigger the flag. A methods comparison or multiple assay types within one coherent study is normally one study. If evidence is ambiguous, set multiple_studies_flag = false. When true, give a concise multiple_studies_reason identifying the concrete evidence for separate studies and why human review may be needed. Do NOT infer pairwise relationships merely to avoid the flag. This is a human-review flag, not an error and not a reason to fail the workflow.

EVIDENCE PRIORITY
For substantive study characteristics, population, facility, system, intervention/exposure, comparator and outcomes: prefer Methods/Materials, then Results/Findings. For research question and objectives, use the Introduction as needed, including earlier introductory material when it clearly establishes the question/aims. Use the Abstract ONLY as an extreme fallback when the information cannot be established elsewhere in the full text.

OUTCOME EVIDENCE — HARD RULE
outcome_measured and impact_type/impact_details must be based ONLY on data actually collected, measured, analysed, or reported as study results by the document itself. Evidence for these fields may come ONLY from Methods/Materials or Results/Findings, including tables and figure legends/captions. Do NOT use evidence from the Abstract, Introduction, Discussion, Conclusions, background, literature review, references, or cited literature for these fields, even if the statement appears to describe the study's implications. If a proposed outcome/impact is supported only outside Methods/Results, leave that outcome/impact field null/empty rather than using the prohibited evidence. This rule overrides any general instruction to provide a complete-looking coding.

EVIDENCE-FIELD CONSISTENCY — HARD RULE
Every evidence item must support the exact field/value it accompanies. Never use evidence from a prohibited section merely because it is convenient or because the statement appears relevant. Before returning JSON, perform a final evidence audit: (1) outcome/impact evidence = Methods/Results only; (2) research-question/objective evidence may use Introduction; (3) all other substantive study-characteristic evidence should preferentially use Methods/Results; (4) Abstract evidence is an extreme fallback only. If the required evidence cannot be found in the permitted sections, return the field null/empty rather than violating the evidence rule.

STUDY TYPE
Use only the closed study_type vocabulary: experimental, observational, modelling, not_stated, not_applicable.
Experimental means investigators deliberately manipulate or impose a condition on study subjects/specimens. In laboratory work, anything deliberately done TO the study subjects/specimens—such as infection/challenge, dosing, treatment, exposure, rearing manipulation, husbandry manipulation, intervention, or other experimental procedure—is experimental, whether or not a comparator exists. A laboratory assay performed only on already-collected material is NOT experimental merely because it occurs in a laboratory or uses laboratory equipment. If subjects/specimens are only observed, measured, sampled, assayed, sequenced, or analysed without deliberate manipulation by the investigators, do NOT code experimental; use observational where appropriate, or not_applicable/not_stated where the study-type framework does not fit.

STUDY DESIGN
Use only: BA, CI, BACI, RCT, Time-series, Modelling, Qualitative, not_stated, not_applicable. Multiple values are allowed when genuinely applicable. CI is appropriate for a genuine comparison of intervention/treatment conditions, including deliberately imposed alternative challenge modes such as injection versus immersion. Do not invent a new design value. If the design is not represented, use not_stated and preserve the authors' terminology in evidence. Time-series and repeated longitudinal/repeated-measures temporal sampling should be coded as Time-series where appropriate; do not create longitudinal as a new value.

RESEARCH APPROACH
Only: quantitative, qualitative, mixed_methods, not_applicable.

SETTING — STUDY SETTING ONLY
Only: field, laboratory, in_vitro, in_silico. Setting describes WHERE the substantive observational or experimental study itself was conducted, not where routine sample processing, laboratory analysis, chemical analysis, microscopy, sequencing, culturing, or quantification was subsequently performed. A field study does NOT become laboratory merely because field-collected samples are processed or analysed in a laboratory. Code laboratory only when the substantive observational or experimental study itself is conducted in a controlled laboratory/research-facility setting (for example, fish are held, exposed, infected, treated, observed, or experimentally manipulated there). Code in_vitro for substantive work outside a whole organism in an in-vitro system; code in_silico for substantive computational work conducted in silico. Never put marine, freshwater, hatchery, land_based, land_based_RAS, open_cages, closed_cages, processing, or any other term in setting.

SPECIES / POPULATION / SAMPLE UNIT / FACILITY / SYSTEM
species is REQUIRED, is a CLOSED ARRAY, and may contain ONLY: Atlantic salmon; chum salmon; pink salmon; coho salmon; chinook salmon; sockeye salmon; masu salmon; rainbow trout; unspecified salmon species.
species means the farmed salmonid species relevant to the study. If the paper explicitly names a permitted salmonid species and the study material/samples/organisms are directly attributable to that species—even if the species itself is not the organism directly measured, such as isolates, parasites, pathogens, or samples originating from that named host—code the named species. Do NOT downgrade to unspecified merely because the immediate study population is a parasite, pathogen, isolate, sediment, or other material. Use unspecified salmon species ONLY when the paper does not explicitly establish a permitted named salmonid species relevant to the study. species must NEVER be null or empty for a complete document. Use multiple permitted species only when multiple qualifying farmed salmonid species are actually studied or explicitly represented by the review as a whole.

other_farmed_species = free-text array for additional farmed species outside the nine-value salmonid species vocabulary, e.g. brown trout or other farmed species. Never put these species into species. Never invent new controlled values for species.

study_population = WHAT population/material is actually studied, e.g. salmon, humans, cleaner fish, sediment-associated organisms, salmon gut contents, salmon fillets, pathogens.
sample_unit = ARRAY of the independently sampled, recruited, assigned, observed, or measured units. Multiple sampling units are permitted when the study genuinely uses different unit types. This is a high-level automated extraction: do NOT attempt to resolve pseudoreplication or statistically determine the single experimental unit. Record the meaningful unit types explicitly used by the study. Never use a species name as sample_unit. Never use a tissue/material such as fillet as sample_unit when the sampled unit is an individual fish; record the tissue/material under system_studied.

There is ONE facility/production-system variable: aquaculture_facility. Do not create or populate farming_system as a separate field.

AQUACULTURE FACILITY — CLOSED VOCABULARY
Only: salmon_farming_region, hatchery, open_cages, closed_cages, land_based, land_based_RAS.
Use aquaculture_facility only for the salmon aquaculture production facility/system in which the study was conducted or the production system being evaluated, when explicitly stated or clearly and unambiguously identified.
CRITICAL LABORATORY RULE: If setting is clearly laboratory, aquaculture_facility MUST be null/empty. Do not code a facility because fish originated there or because the laboratory system resembles one. A laboratory study using recirculated water is NOT a RAS merely because water is recirculated. Only exceptionally code land_based_RAS when the paper explicitly identifies the actual study system as a land-based recirculating aquaculture system/RAS or a clearly recognised equivalent and the laboratory work is genuinely being conducted as part of that production system.
- hatchery: only when explicitly conducted at/in a hatchery facility.
- open_cages: sea pens/open net pens/open cages. For a substantive study conducted in a sea cage, code open_cages by default unless the paper explicitly identifies the cage as a closed cage with impermeable sides/walls or an equivalent recognised closed-cage system. Closed cages in the sea are rare and must be explicit.
- closed_cages: explicitly described closed cages in the sea, specifically including impermeable-sided/walled cages or a recognised equivalent; rare.
- land_based: explicitly described land-based aquaculture production that is not identified as RAS.
- land_based_RAS: explicitly described land-based recirculating aquaculture production/RAS, including a clearly recognised synonymous term. Do not infer RAS from recirculated water alone.
- salmon_farming_region: only when explicitly identified as a salmon-farming region rather than merely naming a farm/location.
Never use wild, mixed, genetic variety/strain, river, marine, freshwater, recirculating alone, or any other invented value in aquaculture_facility.

GENETIC VARIETY
Keep strain/genetic variety separate from aquaculture_facility; record it only in the appropriate free-text field/evidence.

SYSTEM STUDIED
system_studied = the biological, environmental, social system or material actually examined, e.g. sediment, water column, fish gut, fillet tissue, whole fish, farm workforce, supply chain, river ecosystem.

PRODUCTION STAGE — CLOSED VOCABULARY
Only: Feed, Hatchery, Transfer between Hatchery and Adult, Adult grow-out, Processing. Do not create a separate life_stage field. Do not use Roe, Fry, Smolt, broodstock, juvenile, adult, or other invented production-stage values. Roe/fry/smolt are coded Hatchery ONLY when the paper explicitly identifies the study material/fish as part of hatchery production. Do not infer Hatchery from freshwater, juvenile terminology, cultivation centres, or similar context. Movement from hatchery production into adult production is Transfer between Hatchery and Adult. Use Adult grow-out for sea-cage/sea-pen/open-cage/closed-cage production unless the paper explicitly establishes a different production stage. Use Feed and Processing when applicable.

EXPOSURE / INTERVENTION / COMPARATOR / MITIGATION — HARD RULE
intervention = deliberate treatment, manipulation, mitigation measure, vaccination, husbandry change, challenge, or other assigned experimental action.
exposure = an observational exposure whose relationship with an outcome/impact is investigated.
When a mitigation intervention is being tested, intervention is the priority; do NOT automatically also code exposure. Normally intervention and exposure are mutually exclusive. Both only where the same article explicitly measures an exposure/impact relationship AND tests a mitigation intervention.
comparator = ONLY the actual comparison group, site, treatment condition, or intervention condition against which the focal intervention/exposure is compared. Comparator may be null where no genuine comparison exists. Do not code age, season, sampling period, strata, regulatory thresholds, guideline values, background reference values, or benchmarks unless they are actual study comparison conditions.
mitigation_evaluation = ONLY whether/how the study evaluates a measure intended to prevent, reduce, control, or mitigate an adverse impact in the focal study system. Do NOT populate mitigation_evaluation for general treatment efficacy, drug susceptibility, diagnostic assays, assay validation, methodological comparison, or other methodological performance studies unless the evaluated measure is explicitly being tested as a mitigation/control measure for an adverse impact. A study evaluating a bioassay for measuring drug resistance is NOT a mitigation evaluation merely because the assay concerns a treatment drug. If no mitigation measure is actually evaluated, set mitigation_evaluation = null.

OUTCOMES / IMPACTS
outcome_measured = substantive outcomes actually measured/assessed by this document. impact_type and impact_details follow the existing extraction-sheet structure where applicable, subject to the outcome-evidence rule above.

METHODOLOGY
methodology_for_data_collection = actual data-collection methods, using paper terminology where possible. Do not confuse a laboratory analytical method with experimental study type.

RESEARCH QUESTION
Give one concise, consistently phrased research question capturing what the document itself investigates. Use the Introduction as needed; do not restrict extraction to final paragraphs. Use causal language only where justified.

OBJECTIVES
Give a brief 1–2 sentence paraphrase of the document's objective(s).

ONTOLOGY
Apply data/reference/topic_ontology_v3.csv at the same conceptual level used for abstract coding. Use exact path_id values and apply include_when, exclude_when and prompt_logic_note. Prefer the most specific supported node. Do not code topics merely mentioned in background, limitations, or discussion. Provide evidence for selected ontology codes.

METHODS ONTOLOGY
Only code a Methods ontology branch when methodological development, validation, comparison, or evaluation is itself a substantive contribution. Do not code Methods merely because a paper has a Methods section.

FINAL PRE-OUTPUT AUDIT — HARD RULE
Before returning the JSON, check every high-risk rule explicitly. If any proposed value conflicts with a hard rule, correct it before output rather than returning the conflicting value. In particular verify: (1) outcome/impact evidence comes only from Methods/Results; (2) laboratory setting means the substantive study occurred in a laboratory, not merely laboratory analysis of field samples; (3) laboratory setting requires aquaculture_facility = null/empty; (4) Hatchery requires explicit hatchery-facility evidence; (5) sea cage defaults to open_cages + Adult grow-out unless explicitly closed; (6) mitigation_evaluation is null unless an actual mitigation/control measure is evaluated; (7) multiple_studies_flag is true only with strong explicit evidence of separate studies; (8) species is one or more of the nine permitted values and is never null for a complete document; (9) no controlled-vocabulary value has been invented.

EVIDENCE
For every substantive coded field, provide concise supporting evidence. Prefer Methods/Results for study characteristics/outcomes and Introduction for research question/objectives. Abstract evidence is an extreme fallback only. Each evidence item must contain field, value, text, section, and page (null if unavailable).

OUTPUT
Return one JSON object matching coding_schema_v1 exactly. All substantive fields are top-level. Do not add schema descriptions, enum definitions, explanatory top-level keys, or a fields wrapper.
