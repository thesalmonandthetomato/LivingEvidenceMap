The older base prompt contains legacy fields. They are NOT permission to extract additional variables. The current model output is restricted to the current extraction fields listed below, plus the explicitly required audit/evidence structures.

FUNDING
funding_body IS a current extraction field and must be retained. Extract the explicitly named funding body/organisation from the funding statement, acknowledgements or equivalent full text. If applicable but not reported, mark it NOT FOUND. Do not create a separate funder field.

LEGACY / PROHIBITED FIELDS
Do NOT return any field outside the current list above, except field_completeness, not_reported_fields, evidence, and document_completeness_evidence where applicable.

The following are explicitly prohibited model-output fields:
- sample_size
- methodology_for_data_collection
- funder
- intervention
- exposure
- impact_type
- impact_details
- DOI
- year
- source_id
- openalex_id
- schema_version
- run_metadata
- non_methods_results_evidence
- non_methods_results_evidence_fields
- or any other field appearing only because it exists in an older schema/prompt.

Do not let the legacy base prompt's references to these variables cause them to reappear. In particular, sample_size has been deliberately removed from extraction; do not return it at all.

The workflow may maintain provenance/technical metadata outside the model extraction object, but the model must not emit those fields.

COMBINED EXPOSURE/INTERVENTION
There is exactly ONE field: exposure_intervention. Do not output separate exposure or intervention fields. The distinction is intentionally collapsed because it depends on analytical lens and is often minor.

EVIDENCE
Every current extraction field that is substantively coded must have field-specific evidence from the article/full text. Evidence must support that exact field, not merely the article generally. Use enough surrounding context to make the coding auditable. Do not use another paper, cited source, general knowledge, or model inference as the evidence itself. Where a permitted inference is made, cite the underlying article text and identify the inference basis.

COMPLETENESS
field_completeness applies ONLY to the current extraction fields listed above. Its only permitted values are JSON null and the exact string "NOT FOUND".
- Populated/applicable current fields are omitted from field_completeness.
- Applicable but unreported current fields are "NOT FOUND" and appear in not_reported_fields.
- Genuinely inapplicable current fields are JSON null and do not appear in not_reported_fields.
- FOUND is prohibited everywhere in field_completeness.
- NOT_REPORTED and NOT_APPLICABLE are prohibited as completeness-status values.
- No prohibited/legacy field may appear in field_completeness or not_reported_fields.
- not_reported_fields must exactly equal the current fields whose field_completeness value is "NOT FOUND".

LIFE-STAGE INFERENCE
For primary empirical studies, life stage may be inferred from body mass, age, developmental descriptors, or production information ONLY when the supporting information appears in Methods/Materials and Methods or equivalent study-design text for the fish being coded. Do not infer life stage from Introduction, Discussion, abstract, title, cited background literature, or general knowledge alone.

Use this conservative salmon-specific body-mass guideline:
- Atlantic salmon >=1.0 kg may be coded Adult when the fish are in grow-out/production context or otherwise clearly beyond juvenile/smolt size and no contradictory designation is given.
- Atlantic salmon 0.5 to <1.0 kg is borderline and requires additional Methods context supporting Adult.
- Atlantic salmon <0.5 kg must NOT be coded Adult from mass alone.
- For other large-bodied salmon species without a species-specific threshold, the >=1.0 kg Adult rule may be used only when Methods establish a clearly post-juvenile/smolt production context.
- Never infer Smolt, Parr, Fry or Juvenile from body mass alone unless Methods provide additional supporting context.
- If Methods show progression through multiple substantive life stages in the same eligible cohort, code all supported stages.

Production stage and fish life stage remain independent. Pre-market is not itself a permitted fish-life-stage value; if Methods explicitly identify pre-market fish as Adult, Adult may be coded.

NON-PRIMARY SYSTEM/CONTEXT EXTRACTION
Commentaries, perspectives, reviews, editorials, books, book chapters and reports may provide these current system/context fields when explicitly described for eligible salmon/farmed-salmon content: species, other_farmed_species, location_region, location_country, aquaculture_facility, system_studied, production_stage, fish_life_stage, setting, exposure_intervention. These may be supported by any section of the document. Do not inherit empirical study variables from cited studies.

SAMPLE UNIT
sample_unit remains a current extraction field. Code a simple high-level methodological unit when clearly identifiable from the article, preferably ONE primary unit such as fish, cells, farms, communities, grab samples or households. Do not reconstruct pseudoreplication, nesting, statistical units, technical subsamples, derived measurements or tanks merely used as containers. Do not calculate sample size. If no meaningful unit can be identified, mark sample_unit NOT FOUND when applicable.

OUTCOMES
outcome_measured may be coded from the Methods/Materials and Results/Findings of an eligible primary study. Do not transfer outcomes from cited studies into non-primary records. There is no separate impact_type or impact_details field in the current extraction schema.

STUDY TYPE / DESIGN / APPROACH
Use only the controlled vocabularies already defined for the retained fields. Non-primary documents without their own eligible empirical study use the appropriate not_applicable values.

MULTIPLE STUDIES
Set multiple_studies_flag = true only with strong positive evidence of two or more independently structured eligible studies/components. Multiple treatments, factor levels, time points or assays within one coherent design do not suffice. Discussion of multiple cited studies does not by itself make the flag true. If false, multiple_studies_reason is null and is genuinely inapplicable.

FINAL OUTPUT — HARD REQUIREMENT
The model must return exactly these current extraction fields:
document_type, review_type, study_type, study_design, research_approach, setting, sample_unit, study_period, location_region, location_country, species, other_farmed_species, study_population, aquaculture_facility, system_studied, production_stage, fish_life_stage, exposure_intervention, comparator, outcome_measured, funding_body, research_question, objectives_summary, ontology_codes, multiple_studies_flag, multiple_studies_reason.

It may additionally return ONLY field_completeness, not_reported_fields, evidence, and document_completeness_evidence where applicable.

Nothing else. In particular, never return sample_size, methodology_for_data_collection, funder, separate intervention/exposure, impact_type, impact_details, provenance metadata, run metadata, or legacy audit fields.
