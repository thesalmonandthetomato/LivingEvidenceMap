## Explicit blockers to migration authorisation

- Independent W01-Fast automatic decision/scoring parity on the 1,719 October pair identities, classifications, rules and routes. The strict comparator exists, but the experimental independent scoring path does **not**. The original scoring script reads the complete upstream source abstracts to reconstruct its abstract-text features; the recovered candidate and decision tables alone cannot prove scorer equivalence. Do not treat reference-decision replay as independent scoring.
- Real-data affected-existing-work canonical record comparison for the 44 newly joined manifestations, including unchanged-work byte identity, repair/strip handling and lineage. New-singleton scientific-field parity (16 works) is established, but does not settle this requirement.
- End-to-end integration and interrupted transaction recovery, including checkpoints, repeat batch idempotence, pointer rollback and authoritative delta replay. Current primitives are not a proven integrated successor to W01.
- Full-run benchmark and cost/memory assessment at representative scale.
- Production cutover plan must be reviewed and authorised independently by repository owner.

## Proposed controlled cutover, only after blockers pass

1. Pin a frozen production W01 reference and record full provenance, source digests, decision ledger hashes, snapshot IDs and current production pointer.
2. Run W01-Fast on a *separate* isolated state store with read-only frozen W00 inputs. Compare exact stable pair identities, decisions, clusters, canonical JSONL and emitted W02 interface files. No Shiny or Zenodo writes.
3. Re-run an identical batch: verify that no second new decision is appended, work IDs are unchanged, and state pointer and canonical content remain consistent. Simulate interruption before and after checkpoint publication.
4. Run an experimental scheduled-update shadow, without downstream dispatch. Require a bounded runtime/memory/artifact report.
5. Present an explicit owner approval request summarising passed checks, remaining risks and a reversible deployment diff. **Do not automatically promote this branch.**

## Rollback requirements

- Production W01 and its existing baseline remain available and unchanged until owner approves cutover.
- Record old workflow ref, frozen commit, previous authoritative state pointer and hash, and all changed workflow/script files.
- If mismatch or failure occurs before W01-Fast publication: stop experimental run and retain production pointer untouched.
- If an owner-authorised cutover later fails: disable the new entry point, restore the original workflow ref and prior trusted pointer *under an explicit owner-approved procedure*, verify snapshot integrity and historical adjudication linkage, and only then resume downstream work.
- Never silently replay ambiguous transactions, infer identity from numeric offsets, discard undecided human cases, or send unverified output to W02.

## Verified real October decisions (21 October 2026)

Runs `39554714511`, `39555077509`, `39555464339` and `39556497858` provide read-only independent scientific checks, with compact archived audit reports.

- All **1,738 distinct manifestations** in the 1,719 October candidate pairs were located in the October canonical archive through bounded archive reads; zero manifestation identities missing. **436 manifestations have null abstract text in this canonical source**. This is an observed data property, not an extraction failure; original raw-source text parity remains a separate limitation.
- The unchanged production base-scoring script independently scored **1,719 of 1,719** pairs using those recovered individual abstracts and frozen metadata. Its base classifications and rules agreed on all pairs except **160 rule labels**, for which **the classification still agreed**.
- Those 160 pairs were labelled `identifier_safe_preresolve` by production. Independent base scoring instead selected `exact_doi_exact_title` on 121 and `bramer_A` on 39; **every one was classified as duplicate by both paths**.
- The unchanged production deterministic rescorer then independently reproduced the final **rescored classification of every pair (0/1,719 disagreements)**. The 15 initially `review` pairs independently became `duplicate` exactly as in production. **1,559 pairs matched all three fields**: classification, rescored rule, and review route. Only the 160 separately injected identifier-assistance pairs had different rules and routes; their duplicate/non-duplicate classifications agreed.
- Crucially, identifier-safe edge generation itself has **not** been independently validated against the complete original October identifier registry and guards. Do not report complete rule/route parity or migration readiness.
- The actual October final cluster mapping establishes 44 newly appended manifestations joining **44 existing works with 177 historical manifestations**, plus 16 new singleton works. The 16 singleton scientific canonical fields match production; the 44 affected historical works still require affected-only materialisation parity.

Thus the previous blocker described as missing abstracts for the independent candidate scoring is **resolved**. No production or downstream changes are authorised.
